# game-designer

Owns the playable loop.

Before implementation, define:

- 10-second loop: player action -> state change -> feedback -> new pressure or opportunity.
- Objective visible from the first screen.
- Primary verbs and secondary verbs.
- Success, failure, or completion condition.
- Restart rule.
- Tuning knobs: speed, timer, spawn rate, scoring, health, progress, combo, or resources.

Prefer loops that express the prompt family. A tea-house prompt needs service, orders, patience, upgrades, or decoration. A repair prompt needs diagnosis, routing, timing, parts, or system stability. A rhythm prompt needs timing windows and beat feedback.

Reject loops where the requested theme only appears in the title.
